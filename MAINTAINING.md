# Maintaining the site

Personal site and CV of Alexandre Granzer-Guay. Plain HTML generated by a short Python script; the CV PDFs are typeset with Typst from the same data.

## Editing

All content lives in four places:

| What | Where |
|---|---|
| Profile, education, experience, teaching, skills | `data/cv.yaml` |
| Papers and their status | `data/research.yaml` |
| Projects | `data/projects.yaml` |
| Notes | `notes/<slug>.md` (+ optional `notes/<slug>/` for figures) |

Paper status is one of `initialized` (in preparation), `descending` (working paper), `kkt` (under review), `backtracking` (revise and resubmit), `converged` (published). Set `public: true` only once a preprint exists: until then the site and PDFs show title, authors and status only, and the build fails if an abstract, venue or link of an unpublished paper leaks into any output.

`python scripts/build.py --todo` lists open TODOs.

## Building

```bash
uv venv && uv pip install -r requirements.txt   # once
python scripts/build.py                          # site, PDFs and OG image into _site/
python scripts/budget.py _site                   # page weight, requests, script, CV pages
python -m http.server -d _site 8000              # preview
```

Typst 0.15 must be on the PATH. Private CV copies with a phone number (kept out of the repo): `typst compile --root . --input phone="+1 ..." --font-path cv/fonts cv/cv.typ cv-private.pdf`.

The frontier data for the sparse-frontier note is precomputed with `python scripts/frontier.py` (needs `requirements-dev.txt`) and committed.

## How it works

- `scripts/build.py` renders `templates/` with Jinja2, converts LaTeX in notes to MathML at build time, and writes JSON-LD, `sitemap.xml`, `robots.txt`, `llms.txt`, `llms-full.txt`, Markdown twins, `cv.json` (JSON Resume) and an Atom feed.
- `scripts/contours.py` draws the header: level sets of a smoothed sparse risk-parity objective over two portfolio weights, with a heavy-ball descent path from a different start on every page.
- `scripts/measure.py` measures each page; the footer prints the numbers as a solver log, and `scripts/budget.py` fails CI if a page breaks its budget.
- `.github/workflows/pages.yml` builds, checks budgets, validates HTML, checks links and deploys to GitHub Pages on every push to `main`.

The previous site (Create React App) is preserved on the `source` and `master` branches.
